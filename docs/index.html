Is the recipe we're costing the recipe we're actually building?

Tesla books vehicles at standard cost. When a design change goes live before the standard is re-rolled, or the floor quietly uses parts differently from the bill of materials, the variance report fills with noise and real waste hides inside it. This close check reconciles the floor system with the ERP first, then separates the noise, finds the drift, and prices the parts left behind.

All data is synthetic: one simulated month on a Giga Texas-like line. Source systems are shaped like Tesla's public picture: an ERP like Warp (MySQL), a floor system like MOS, and a PLM for design changes. Table design and thresholds are assumptions, not Tesla's.

Built with MySQL, Airflow, SQL and Python, FastAPI, Docker and GitHub Actions. Code and write-up on GitHub. Click any row with a work order to see the floor events and ERP rows behind its number. This page shows a saved run of the pipeline; run it locally with Docker to see it live.
